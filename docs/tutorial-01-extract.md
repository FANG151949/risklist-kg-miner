# 教程 01：v0.1 规则抽取器

## 需求（谁提的、原来怎么痛）

业务同事维护高风险人员名单，信息来源之一是各地方政府网站发布的**任免公示**。
原来的做法：人工打开网页，逐条把"谁、在哪个机构、任什么职务、什么时间"抄进 Excel。
一份公告 5~20 条记录，一天要处理几十份，抄错字、漏条目、事后找不到出处是常态。

**验收标准**：丢一份公告文本进去，工具输出结构化记录，每条带行号，能回溯到原文。

## 步骤 1：跑起来看效果

```bash
cd ~/projects/risklist-kg-miner
uv run python -m risklist_kg_miner.extract data/samples/notice-001.txt
```

预期输出：

```
L11 任命 陈志远 -> 河州市发展和改革委员会 / 副主任 (生效 2026-09-01)
L12 任命 林慧敏 -> 河州市教育局 / 副局长 (生效 2026-09-01)
L13 任命 赵天宇 -> 河州市国有资本运营有限公司 / 董事长 (生效 2026-09-01)
L14 免去 王建国 -> 河州市财政局 / 局长 (生效 2026-09-01)
L15 免去 孙丽华 -> 市卫生健康委员会 / 副调研员 (生效 2026-09-01)
共 5 条任免记录
```

对照 `data/samples/notice-001.txt` 的 L11~L15 看：每条输出的行号和原文一一对应。

## 步骤 2：观察正则怎么工作

打开 `src/risklist_kg_miner/extract.py`，找到 `APPOINTMENT_RE`。注意三点：

- 行首锚定 `^` + 结尾 `[；;。]`：只匹配"一整条任免记录"的行，正文里提到"任命"二字的普通句子不会被误捕。
- `(?:为|的)`：任命行用"为"，免去行用"的"，两种句式都覆盖。
- 机构名用后缀集合（委员会/局/公司/院/部/中心）切分，剩下的部分就是职务。

## 步骤 3：fail-soft 实验

```bash
uv run python
```

```python
from risklist_kg_miner.extract import extract_appointments
extract_appointments("今天天气不错，没有任何任免内容。")   # -> []
extract_appointments("任命 张三 为 某局副局长；")            # -> 1 条记录
```

观察：匹配不上不报错，返回空列表。采集场景里来源格式千差万别，**宁漏勿炸**——
漏掉的后面有校验环节兜底，崩了就什么都没了。

## 步骤 4：归纳 v0.1 的价值与痛点

价值：规则是确定性的——零调用成本、零幻觉、每条结论带行号可回溯、可以单测。

痛点（引出下一版）：

1. **版式一变就瞎**：换个网站，任免行可能写成"经研究，陈志远同志任……"，
   正则立即失效 → v0.2 用采集 agent + 阅读循环处理异构来源。
2. **机构名简写不一致**：L15 的"市卫生健康委员会"缺"河州"前缀，和同市的其他
   机构名对不上 → 归一化交给 v0.3 校验层 / v0.4 图谱层。

## 步骤 5（动手，你自己完成）

1. 在 `data/samples/notice-001.txt` 里加一行：
   `任命 周晓梅 为 河州市交通运输局副局长；`
2. 重跑步骤 1 的命令，观察输出变成 6 条、新记录行号正确。
3. `uv run pytest -q` 确认测试全红——**故意的**：样例数据变了，旧断言
   "共 5 条"就不成立了。把 `tests/test_extract.py` 里写死的 5 改成 6，
   行号列表 `[11, 12, 13, 14, 15]` 相应调整，再跑直到全绿。
4. 体会这一步教的道理：**测试断言的是"对业务的承诺"，数据变了承诺就要跟着变**，
   而不是测试坏了就删测试。
5. 自己提交：

```bash
git add -A
git commit -m "feat: 样例公告补充交通运输局任命记录，测试同步更新"

```
