# 教程 07：v0.7 评测与消融（用数据回答"引入图谱值不值"）

## 需求（谁提的、原来怎么痛）

面试官/评审的一句话就能问死前六版："你说三路召回比两路好、说版式适配
全都能抽、说合并层可靠——**证据呢？**"没有评测的 RAG 只能'感觉准'。

**验收标准**：标注集上给出抽取层 P/R、检索层 recall@8 / precision@8 / MRR，
且两路 vs 三路、离线 vs 真嵌入的对比有数字支撑。

## 核心优势：合成语料 = 我们握有全部真相

真实业务里标注集要人工标（贵、慢、有错）。合成语料天然自标——
`data/eval/ground_truth.json` 写下 14 条记录真相和 10 个查询的相关行，
这就是"带评估体系"的底气：**数据红线反过来成了评测红利**。

## 步骤 1：跑评测

```bash
uv run python -m risklist_kg_miner.evals                # 离线确定性
uv run --env-file .env python -m risklist_kg_miner.evals # 补真嵌入两行
```

实测结果（2026-10-12，语料 40 行 / 10 查询）：

| 层 | 指标 | 结果 |
|---|---|---|
| 抽取层 | precision / recall | **100% / 100%**（三种版式 14 条全对，零差异） |
| 合并层 | 组数 / 冲突数 | 11 组 / 1 冲突，通过 |

| 检索消融（top-8） | recall@8 | precision@8 | MRR |
|---|---|---|---|
| 两路·离线哈希向量 | 90% | 21% | 0.850 |
| 三路·离线哈希+图谱 | 90% | 16% | **0.900** |
| 两路·百炼真嵌入 | **100%** | 18% | 0.875 |
| 三路·百炼真嵌入+图谱 | **100%** | 18% | **0.925** |

## 三个结论（每行都是可复现实验，不是感觉）

1. **真嵌入的价值：缩略语语义鸿沟**。唯一漏检是"卫健委的人事变动"——
   "卫健委"与"卫生健康委员会"的滑动二元组几乎不重叠，BM25/哈希向量/
   图谱三路全部失效（图谱实体是全称，问题里是简称）。百炼真嵌入
   理解"卫健委 ≈ 卫生健康委员会"，recall 90% → 100%。
   这是本项目里"语义召回"最直接的量化证据。
2. **图谱路的价值：排序质量而非召回**。图谱路在本集不提升 recall
   （top-8 够宽，BM25 已把相关行装进来），但 MRR 稳定 +0.05
   （0.850→0.900 离线，0.875→0.925 真嵌入）：把相关行排得更靠前。
   代价是 precision@8 略降（同源噪声行被带进候选）——召回与精排的
   分界，正好是 rerank 的用武之地（见下）。
3. **诚实的边界**。语料 40 行、查询 10 个，图谱的多跳优势（"和陈志远
   同机构任职过的都有谁"这类查询）在本集没有体现——评测敢报"本集
   无 recall 增益"才是真评测。简历口径："消融显示图谱主要提升排序
   质量（MRR +0.05），缩略语查询依赖语义向量；多跳查询增益需更大
   标注集验证。"

## Rerank 决策：数据已齐，方向明确

v0.5 预留的 rerank 现在有决策依据了：三路 recall@8 已 100%，短板是
precision@8 只有 18%（top-8 里挤着 6-7 行噪声）。cross-encoder 精排
恰好是"召回全但排序混"的解药——**做 rerank 的条件成熟，列入 v0.8+**。

## 步骤 2：指标怎么算（src/risklist_kg_miner/evals.py）

- 抽取层：预测/真相都转 `(来源, 动作, 人, 机构, 职务)` 五元组集合，
  交集算 TP——集合比对，天然容忍行号差异；
- recall@k = 命中相关行 / 全部相关行；precision@k = 命中 / k；
- MRR = 首个相关行名次倒数的平均——衡量"第一条给对没有"；
- 全部离线确定性（哈希向量），测试可钉死数字；真嵌入两行只在配了
  key 的 demo 里跑。

tests/test_evals.py 钉死的承诺：标注引用的行都真实存在；抽取层全对；
漏检恰好且仅是卫健委查询的两行（`test_semantic_gap_query_is_the_only_miss`）；
离线三路 MRR > 两路。

## 步骤 3（动手）：加一个评测查询

往 `ground_truth.json` 的 queries 里加一条，比如
`{"query": "唐雪担任什么职务", "relevant": ["notice-002#L6"]}`，
重跑评测和 pytest——观察指标变化，这就是"评测驱动迭代"的最小循环。
commit 后这行查询从此防止检索退化。

## 面试 hook

- "怎么证明你的 RAG 有效？" → 三层评测（抽取 P/R、合并组数冲突数、
  检索 P@k/R@k/MRR）+ 四配置消融矩阵，每个数字可离线复现。
- "图谱到底带来了什么？" → 分场景回答：缩略语靠语义向量、图谱提排序
  (MRR+0.05)、多跳要大数据集——比"图谱很强大"可信一百倍。
- "评测集哪来的？" → 合成语料自标注（顺带讲数据合规红线意识）。
